# DCP 配置文件

> 本文是[英文规范](README.md)的参考译文，更新于 25/10/2026。**具有规范效力的是英文版**：本译文不具规范效力，如有出入，以英文版为准。标识符和代码块保持原文，不作翻译。

配置文件是基于 [DCP 核心](../core/) 构建的扩展，用于满足特定的部署需求。基本互操作并不需要它们：一个符合要求的核心实现即使没有任何配置文件也是有效的。

<a id="available-profiles"></a>

## 可用的配置文件

| 配置文件 | 范围 | 目录 |
|---------|-------|-----------|
| **Crypto** | 算法选择、混合/PQ 签名、复合绑定、密码敏捷性、验证器策略 | [crypto/](crypto/) |
| **A2A** | 代理发现、会话建立、传输绑定、消息交换 | [a2a/](a2a/) |
| **Governance** | 风险等级、司法管辖区证明、吊销、密钥恢复、治理仪式 | [governance/](governance/) |
| **Admission** | 在验证之上的委托人信任集和由运营方固定的 `strict-v1` 配置文件 | [admission/](admission/) |

<a id="design-principles"></a>

## 设计原则

- 配置文件不得（MUST NOT）与 DCP 核心的要求相矛盾
- 配置文件可以（MAY）定义额外的工件、字段或验证步骤
- 配置文件可以（MAY）指定算法选择、传输绑定或治理策略
- 一个符合要求的核心实现即使没有任何配置文件也是有效的
- 配置文件独立于核心进行版本管理

<a id="relationship-to-existing-specs"></a>

## 与现有规范的关系

配置文件的结构为仓库中已有的材料提供了一个组织框架：

- **Crypto 配置文件**取材于 [DCP-AI v2.0](../DCP-AI-v2.0.md) 第 2–5 节（算法、复合签名、验证模式）
- **A2A 配置文件**取材于 [DCP-04](../DCP-04.md)（代理之间的通信）
- **Governance 配置文件**取材于 [DCP-AI v2.0](../DCP-AI-v2.0.md) 第 13–14 节（治理、自适应安全等级）和 [DCP-01](../DCP-01.md)（司法管辖区证明、吊销）

现有的规范性规范仍具权威性。这些配置文件的 README 提供编辑性背景，并解释核心与配置文件关注点之间的分离。
