# DCP のプロファイル

> [英語の仕様](README.md)の参考訳です（25/10/2026 更新）。**規範となるのは英語版です**。この翻訳に規範的な効力はなく、内容が異なる場合は英語版が優先されます。識別子とコードブロックは翻訳せずにそのまま掲載しています。

プロファイルは、特定の展開の必要に応えるために [DCP コア](../core/) の上に築く拡張です。基本的な相互運用には必要ありません。適合したコアの実装は、プロファイルがなくても有効です。

<a id="available-profiles"></a>

## 利用できるプロファイル

| プロファイル | 範囲 | ディレクトリ |
|---------|-------|-----------|
| **Crypto** | アルゴリズムの選択、ハイブリッド/PQ の署名、複合の結び付け、暗号の俊敏性、検証器のポリシー | [crypto/](crypto/) |
| **A2A** | エージェントの発見、セッションの確立、伝送の結び付け、メッセージの交換 | [a2a/](a2a/) |
| **Governance** | リスクティア、管轄区域の証明、失効、鍵の回復、ガバナンスの儀式 | [governance/](governance/) |
| **Admission** | 検証の上に置く、プリンシパルの信頼セットと運用者が定める `strict-v1` のプロファイル | [admission/](admission/) |

<a id="design-principles"></a>

## 設計の原則

- プロファイルは DCP コアの要件と矛盾してはならない（MUST NOT）
- プロファイルは追加のアーティファクト、フィールド、検証の手順を定義してもよい（MAY）
- プロファイルはアルゴリズムの選択、伝送の結び付け、ガバナンスのポリシーを指定してもよい（MAY）
- 適合したコアの実装は、プロファイルがなくても有効である
- プロファイルはコアとは独立にバージョン付けされる

<a id="relationship-to-existing-specs"></a>

## 既存の仕様との関係

プロファイルの構成は、リポジトリにすでにある内容を整理する枠組みを提供します：

- **Crypto プロファイル**は [DCP-AI v2.0](../DCP-AI-v2.0.md) の 2–5 節（アルゴリズム、複合署名、検証モード）に基づきます
- **A2A プロファイル**は [DCP-04](../DCP-04.md)（エージェント間の通信）に基づきます
- **Governance プロファイル**は [DCP-AI v2.0](../DCP-AI-v2.0.md) の 13–14 節（ガバナンス、適応的なセキュリティティア）と [DCP-01](../DCP-01.md)（管轄区域の証明、失効）に基づきます

既存の規範的な仕様が引き続き基準です。これらのプロファイルの README は編集上の文脈を与え、コアとプロファイルの関心事の分離を説明するものです。

<a id="implementation-notes-informative"></a>

## 実装に関する注記（参考）

> **2026 年 10 月 25 日に追加。規範的ではありません。** これらの注記は要件を加えず、上の内容を何も変えません。`main` のリファレンスの
> コードがこの文書とどう関係するかを説明するものです。食い違う場合は、上の規範的な本文がそのまま有効です。

- 「プロファイルがなくても有効」とは、コアのアーティファクトの相互運用についてのことです。実装をコアの要件から
  免除するものではなく、展開は引き続き自らの検証器のポリシー（たとえばリスクティアが求める検証の
  モード）と、使う場合はアドミッションのプロファイルを適用します。
- 検証を通るバンドルは、内部で一貫しており、それ自身が列挙する鍵で署名されています。それだけでは、その
  プリンシパルが信頼されることにも、受け入れられることにも、行動が認可されることにもなりません。プリンシパルへの信頼は、
  検証器自身の信頼セットから来ます。[docs/ADMISSION.md](../../docs/ADMISSION.md) と [アドミッションのプロファイル](admission/) を参照してください。
