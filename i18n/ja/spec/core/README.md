# DCP コア

> [英語の仕様](../../../../spec/core/README.md)の参考訳です（25/10/2026 更新）。**規範となるのは英語版です**。この翻訳に規範的な効力はなく、内容が異なる場合は英語版が優先されます。識別子とコードブロックは翻訳せずにそのまま掲載しています。

このディレクトリには、Digital Citizenship Protocol の**コアの仕様**、つまりすべての DCP の実装がサポートしなければならない、最小限の相互運用可能なプロトコルの範囲が入っています。

<a id="what-is-dcp-core"></a>

## DCP コアとは

DCP コアは、どの検証器でも次を評価できるようにする、アーティファクト、その関係、検証のモデルを定義します：

- エージェントに**誰が責任を負うか**（責任を負うプリンシパルへの結び付け）
- エージェントが何をするつもりだと**宣言したか**（意図の宣言）
- **どのポリシーの結果**が適用されたか（ポリシー判断）
- **どの検証可能な証拠**が作られたか（行動の証拠 / 監査証跡）
- 持ち運べる検証のために、**すべてのアーティファクトがどうまとめられるか**（バンドルのマニフェスト）

コアは意図的に最小限です。*何が*存在しなければならないか、それを*どう*検証するかを定義しますが、*どう*署名するか、*どの*アルゴリズムを使うか、エージェントが互いを*どう*見つけるか、ガバナンスのポリシーを*どう*適用するかは**プロファイル**に委ねます。

<a id="core-artifacts"></a>

## コアのアーティファクト

| アーティファクト | 目的 | 既存の仕様 |
|----------|---------|---------------|
| Responsible Principal Record | エージェントを人または法人に結び付ける | [DCP-01](../../../../spec/DCP-01.md)（「Responsible Principal Record」として） |
| Agent Passport | エージェントのアイデンティティ、能力、鍵の材料 | [DCP-01](../../../../spec/DCP-01.md) |
| Intent Declaration | 行動の前の構造化された宣言 | [DCP-02](../../../../spec/DCP-02.md) |
| Policy Outcome | 意図に対する認可の判断 | [DCP-02](../../../../spec/DCP-02.md) |
| Action Evidence | ハッシュチェーンでつながった監査エントリー | [DCP-03](../../../../spec/DCP-03.md) |
| Bundle Manifest | すべてのアーティファクトを結び付ける持ち運べるパッケージ | [BUNDLE](../../../../spec/BUNDLE.md) |

<a id="relationship-to-existing-specs"></a>

## 既存の仕様との関係

コアの仕様は、既存の規範的な仕様（DCP-01 から DCP-03、BUNDLE、VERIFICATION）を 1 つの一貫したコアにまとめる編集上の層です。それらを置き換えるものではなく、プロトコルの最小限の範囲を一望できるようにするものです。

<a id="what-is-not-core"></a>

## コアではないもの

次のものは明示的にコアの外にあり、プロファイルやサービスに属します：

- 特定の暗号アルゴリズム（Ed25519、ML-DSA-65 など）→ [Crypto プロファイル](../../../../spec/profiles/crypto/)
- エージェント間の発見と通信 → [A2A プロファイル](../../../../spec/profiles/a2a/)
- リスクティア、管轄区域、失効、ガバナンス → [Governance プロファイル](../../../../spec/profiles/governance/)
- 検証サーバー、アンカリング、透明性ログ → インフラのサービス

## 実装に関する注記（参考）

> **2026 年 10 月 25 日に追加。規範的ではありません。** これらの注記は要件を加えず、上の内容を何も変えません。`main` のリファレンスの
> コードがこの文書とどう関係するかを説明するものです。食い違う場合は、上の規範的な本文がそのまま有効です。

- コアのアーティファクトには、通信路上の 2 つのバージョンがあります。V1（`schemas/v1/`）：マニフェストなし、`SignedPayload` のエンベロープなし、
  `session_nonce` なし、バンドルに対する 1 つの Ed25519 の署名、そして少なくとも 1 つの監査エントリー。V2（`schemas/v2/`、
  [DCP-AI v2.0](../../../../spec/DCP-AI-v2.0.md) で規定）：各アーティファクトを約束する署名付きのマニフェスト、RPR、パスポート、意図、
  ポリシー判断のための `SignedPayload` のエンベロープ、セッションの nonce、複合署名、そして空でもよい
  監査証跡。
- V2 では、RPR がプリンシパルの `binding_keys` を持ち、パスポートはエージェント自身の鍵で署名されます。検証を通る
  バンドルが証明するのは、その署名が列挙された鍵と一致することであって、プリンシパルが誰かではありません。信頼は
  検証器の信頼セットから来ます（[docs/ADMISSION.md](../../../../docs/ADMISSION.md)）。
