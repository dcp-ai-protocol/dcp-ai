# DCP-AI アーリーアダプター・プログラム

> [英語版](../../../docs/EARLY_ADOPTERS.md)の参考訳です（25/10/2026 更新）。内容が異なる場合は英語版が優先されます。識別子、コマンド、コードブロックは翻訳せずにそのまま掲載しています。

**状況：** 受付中 — 随時受け入れ
**ライセンス：** Apache-2.0（参加費用は不要）

<a id="what-it-is"></a>

## プログラムの概要

DCP-AI は、AI エージェントのための持ち運び可能な説明責任のレイヤーです。暗号学的なアイデンティティ、機械が読める意図、改ざんを検出できる監査証跡、エージェント間通信、ライフサイクルのガバナンス、委任による代理を提供します。スタック全体はオープンソースで、主要なすべてのレジストリからインストールできます。

アーリーアダプター・プログラムは、実際のシステムに AI エージェントをデプロイしているチームに、DCP-AI を統合し、仕様だけのレビューでは見つけられないエッジケースを明らかにし、プロトコルの次の版を直接形作ってもらうための招待です。

これはベータテストではありません。SDK は公開され、使われています。これは共同設計のパートナーシップであり、あなたの統合の経験が、次のリリースの設計の一部になります。

<a id="who-should-apply"></a>

## 応募してほしい人

- エージェントのフレームワークやオーケストレーションを構築している **AI プラットフォームのチーム**
- 責任、監査、規制遵守が重要な場面で自律型エージェントをデプロイしている **企業のチーム**
- 検証可能なエージェントのアイデンティティを必要とする **金融、医療、公共部門のチーム**
- エージェントの安全性、ポスト量子暗号、検証可能な資格情報に取り組んでいる **研究者**
- 新しいエージェント製品を出していて、学んだことを共有してくれる **個人の開発者**

<a id="what-early-adopters-get-on-top"></a>

### アーリーアダプターがさらに得られるもの

- GitHub の Issues/Discussions を通じた**メンテナーとの直接の窓口**。2 営業日以内の返答と、作業を妨げる問題の最優先の振り分け。
- 今後のリリースのロードマップへの**共同設計の意見**：どのセキュリティティアか、どのアルゴリズムか、ワイヤ形式についてどう判断するか。
- **適合性の検証**：あなたの統合の経路を実際に試すテストスイートの作成を支援し、その結果を公開の適合性スイートに反映します。
- **事例研究での協力**（任意）：あなたの統合について、アーキテクチャ上の判断、課題、成果を記した記事を、すべての段落にあなたの承認を得たうえで公開します。
- **ガバナンスへの道**：積極的なコントリビューターは、[GOVERNANCE.md](../../../GOVERNANCE.md) に従って Reviewer や Maintainer に招待されます。

<a id="what-we-ask"></a>

## お願いしたいこと

<a id="integration"></a>

### 統合

1. 開始から 90 日以内に、少なくとも 1 つのステージングまたは本番の経路に DCP-AI の SDK を統合する。
2. 主要な流れをエンドツーエンドで実装する：アイデンティティの結び付け → 意図の宣言 → ポリシー判断 → 監査エントリ → バンドルの検証。
3. v2.0 ではハイブリッドな複合署名（Ed25519 + ML-DSA-65）を使う。SDK が代わりに行うので、自分で実装する必要はない。
4. あなたの統合に対して適合性テストスイートを実行し、結果を共有する。

<a id="feedback"></a>

### フィードバック

1. 月に 1 回、構造化されたフィードバックを送る。GitHub の Discussion、メール、短い通話のうちやりやすいもので。
2. バグやエッジケースは GitHub の Issue として登録する。セキュリティに関わる発見には、GitHub の非公開の脆弱性報告を使う。
3. 設計上の判断が検討されている公開の議論のスレッドに、少なくとも 1 つ参加する。

<a id="testing"></a>

### テスト

1. 依存している暗号のプリミティブ（Ed25519、ML-DSA-65。該当すれば ML-KEM-768 と SLH-DSA-192f）について NIST KAT の検証を実行する。
2. 同じシステムで複数の SDK を使う場合は、SDK 間の相互運用のベクター（`tests/interop/v2/`）を実行する。
3. パイプラインに v1.0 のバンドルがあれば、それとの後方互換性を検証する。
4. 壊してみる：バンドルの改ざん、署名の除去、セッションのつなぎ合わせ、リプレイ。壊せたなら、ぜひ教えてほしい。

<a id="timeline"></a>

## スケジュール

プログラムは随時受け入れです。あなたの時計は、参加を承諾した時点から動き始めます。

| フェーズ | 典型的な期間 | 内容 |
|---|---|---|
| オンボーディング | 1 週目 | キックオフの通話やスレッド。あなたのスタックに合わせたプロトコルの説明。統合計画の草案。 |
| 統合 | 2〜8 週目 | 主要な流れを構築。最初の適合性テストの実行。最初の障害の発生。メンテナーの助言を得て解消。 |
| 堅牢化 | 9〜12 週目 | セキュリティティアの調整。NIST KAT の網羅。該当すれば SDK 間の相互運用。本番への備えのレビュー。 |
| 修了 | 13 週目以降 | エコシステムの正式な参加者になる。希望していれば事例研究の草案を作成。ガバナンスへの道が開く。 |

正式な「終了日」はありません。リリースを続け、フィードバックの循環が続いている限り、プログラムに残れます。

<a id="how-to-apply"></a>

## 応募方法

<a id="process"></a>

### 手順

1. [`dcp-ai-protocol/dcp-ai`](https://github.com/dcp-ai-protocol/dcp-ai/discussions) で、**Early Adopter Application** のテンプレートを使って GitHub の Discussion を開きます（Discussion が使えない場合は、`early-adopter` ラベルを付けた Issue を開きます）。
2. あるいは、メンテナーにメールします（現在のメンテナーの連絡先は [GOVERNANCE.md](../../../GOVERNANCE.md) を参照）。

<a id="what-to-include"></a>

### 記載してほしいこと

- 組織またはチームの名前と簡単な説明
- ユースケース：どのようなエージェントをデプロイしている、またはデプロイする予定か
- 技術スタック：言語、フレームワーク、インフラ
- DCP のどのコンポーネントが最も関係するか（DCP-01 のアイデンティティ？ DCP-03 の監査？ DCP-07 の仲裁？ すべて？）
- スケジュール：いつ始められるか
- チームの規模：統合に何人のエンジニアが関わるか

<a id="review"></a>

### 審査

応募は随時審査し、通常は 7 営業日以内に行います。規模で選ぶのではなく、企業のコンプライアンス、研究、個人の開発者など、さまざまなユースケースが混ざるようにしています。

<a id="selection-criteria"></a>

## 選考基準

- **ユースケースの多様性**：想定どおりの企業の使い方だけでなく、珍しい用途を積極的に求めています。
- **実際にデプロイする意図**：評価だけでなく、実際のシステムに出すチームを優先します。
- **関与**：良いことも悪いことも、見つけたことを共有してくれること。
- **技術力**：暗号プロトコル、エージェントのシステム、セキュリティに関わるインフラの経験があるチームであること。

## セキュリティの開示

> **注記（2026 年 10 月 25 日）：文書間で記述が食い違っています。** [SECURITY.md](../../../SECURITY.md) は深刻度ごとに固定の報奨金の範囲を挙げていますが、このページと [GOVERNANCE.md](../../../GOVERNANCE.md) は報奨金を報告ごとに決めるとしています。どちらが適用されるかをメンテナーが確認するまで、両方の文章をそのまま残しています。

脅威モデルと報告の手引きについては [SECURITY_MODEL.md](../../../docs/SECURITY_MODEL.md) を参照してください。

<a id="faq"></a>

## よくある質問

**Q：DCP-AI は本番で使える状態ですか？**
A：v2.0 の仕様は完成しており、5 つの SDK は公開され、使われています。DCP-04 から DCP-09 のヘッダーには「Published — v2.0 (extension; revisions tracked via adopter feedback)」というラベルがあります。ワイヤ形式は安定してテストされており、ポイントリリースの改訂は互換性を壊す変更ではなく、アダプターのフィードバックに基づいて行われます。あなたのデプロイで使える状態かどうかは、使う部分によります。

- SDK の検証器が本番での経路です。リファレンスサービスは状態をメモリーに保持し、リファレンスのゲートウェイの DCP-05–09 のエンドポイントには認証がありません（[OPERATOR_GUIDE.md](../../../docs/OPERATOR_GUIDE.md)）。
- リポジトリには HSM との統合がなく、`@dcp-ai/cli init` のウィザードはデモです（[SECURITY_MODEL.md](../../../docs/SECURITY_MODEL.md)、「Known Limitations and Mitigations」）。

2026 年 2 月 26 日の v2.0 の最終セキュリティ監査（[spec/AUDIT-v2.0-FINAL.md](../../../spec/AUDIT-v2.0-FINAL.md)）は日付のある記録です。その後のレビューで、監査が報告していなかった制限が見つかっています。たとえば、監査での HSM の欠落は、シミュレーションのプロバイダーで埋められただけでした。

**Q：アーリーアダプター・プログラムへの参加に費用はかかりますか？**
A：かかりません。プログラムは無料です。プロジェクト全体が Apache-2.0 です。

**Q：ポスト量子の機能を使わなければなりませんか？**
A：検証者によります。V2 のバンドルはクラシカルのみの署名を持つこともできます。検証者は `hybrid_required` モードでハイブリッドな複合署名（Ed25519 + ML-DSA-65）を要求します。このモードは elevated と maximum のティアのアクションに適用され、リファレンスサーバーの既定です。ハイブリッド鍵を使えば SDK が両方に署名するので、暗号を自分で書く必要はありません。

**Q：個人の開発者として参加できますか？**
A：できます。個人の開発者や小さなチームも歓迎です。最も興味深いエッジケースを見つけるのは、そうした人たちであることが少なくありません。

**Q：プログラムを修了したらどうなりますか？**
A：引き続き DCP-AI を使ってください。積極的なコントリビューターは、[GOVERNANCE.md](../../../GOVERNANCE.md) に従って Reviewer や Maintainer に招待されます。

**Q：サービスを自分でホストして運用できますか？**
A：できます。それが想定しているモデルです。検証サーバー、アンカー、透明性ログ、失効レジストリは、すべて GHCR で Docker イメージとして公開されており、Fly.io の設定も [`deploy/`](../../../deploy/) にあります。ファーストパーティーの SaaS はなく、各オペレーターが自分で運用します。これらはリファレンスサービスなので、公開する前に永続的なストレージを追加し、ゲートウェイの認証のない DCP-05–09 のエンドポイントへのアクセスを制限し、[OPERATOR_GUIDE.md](../../../docs/OPERATOR_GUIDE.md) を読んでください。

**Q：論文で DCP-AI をどう引用すればよいですか？**
A：論文とソフトウェアの両方の DOI は [CITATION.cff](../../../CITATION.cff) を参照してください。
