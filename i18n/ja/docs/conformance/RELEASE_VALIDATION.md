# リリース検証

> [英語版](../../../../docs/conformance/RELEASE_VALIDATION.md)の参考訳です（10/11/2026 更新）。内容が異なる場合は英語版が優先されます。識別子、コマンド、コードブロックは翻訳せずにそのまま掲載しています。

リリースの公開後、[`tools/release-validation`](../../../../tools/release-validation/README.md) は、新しいコンシューマーが行うのと同じように、公開済みパッケージを公式レジストリからインストールし、インストールされたものに対して外部適合性カタログを実行します。このページでは、それが何を示すのか、これまでに何が実行されたのか、何が対象外なのかを説明します。実行方法のリファレンスは、ツールの README です。

<a id="what-it-covers"></a>

## 対象範囲

09/11/2026 に公開された 6 つのバージョン（[監査ドシエ](../../../../docs/conformance/AUDIT_DOSSIER.md#publication-of-09112026)）を、9 つのレーンで検証します。

| 公開済みバージョン | レーン |
|---|---|
| npm `@dcp-ai/sdk` 2.4.0 | `npm-sdk` |
| npm `@dcp-ai/wasm` 2.2.0 | `npm-wasm-node`（Node）と `npm-wasm-browser`（実際の Chrome） |
| npm `@dcp-ai/cli` 2.2.0 | `npm-cli` |
| PyPI `dcp-ai` 2.11.0 | `pypi-wheel`（wheel）と `pypi-sdist`（ソースからビルドした sdist） |
| Go モジュール `sdks/go/v2` v2.14.0 | `go` |
| crates.io `dcp-ai` 2.14.0 | `crates-default` と `crates-otlp`（`otlp` feature 付き） |

各レーンは、専用に構築した環境を持つ一時ディレクトリにパッケージをインストールし、ダウンロードしたバイト列が公開されたものであること、インストールまたはコンパイルされるものがそのバイト列であることを確認します。そのうえで初めて、次の証拠を実行します。

- **60 のカタログセル。** [適合性キット](../../../../tools/conformance/README.md)の 8 つの外部カタログを 6 つのレーン（SDK、Python の 2 レーン、Go、Rust の 2 レーン）で実行し、WebAssembly API に適用される 6 つのカタログをその 2 つのレーンで実行します。CLI のレーンにはカタログがありません。このリビジョンのカタログでは 6142 ケースになります。
- ブラウザー上の公開 API `DcpWasm` の **103 の直接ケース**。
- インストール済みの CLI に対する **CLI の 4 つのスイート**（218 テスト）と、そのネガティブコントロール。
- 同じ実行内の **58 のコントロール**。一部は合格しなければならない肯定的なコントロールです。残りは、実際のレポートを改変したコピー、反転した期待値、注入した障害、タイムアウト、ローカルの取得元で、それぞれが求められているとおりの形で拒否されなければなりません。

このツール独自のカタログや期待値は追加しません。期待値はキットのもので、このリポジトリにコミットされています。

<a id="what-a-result-means"></a>

## 結果の意味

- **PASS** には、上記のすべてが 1 回の実行で必要です。これらのアーティファクトが、これらのハッシュで、これらのレジストリから取得され、このリビジョンのキットにより、この環境で、これらのカタログに合格したことを述べます。認証ではなく、実行されなかった環境については何も述べません。
- **PARTIAL** は、失敗のなかった一部のレーンまたはカタログの選択です。診断であり、合格として報告されることはありません。
- **不一致**は、インストールされたアーティファクトが応答したものの、コミットされた期待値と一致しないことを意味します。
- **エラー**は、判定できる有効な応答がなかったことを意味します。レジストリ、ネットワーク、ツールチェーン、一致しない同一性、不完全なレポートやこの実行のものではないレポートなどが原因です。エラーがプロトコルによる拒否として数えられることはなく、合格として数えられることもありません。

パッケージをインストールして取得元を確認することは、適合性ではありません。動作についての証拠になるのは、カタログセルとブロックだけです。

このツールはプロトコルを一切変更しません。正規化プロファイル `dcp-jcs-v1`、コア、SDK、カタログは、そのまま使用します。

<a id="running-it"></a>

## 実行方法

```bash
node --test tools/release-validation/release-validation.test.mjs
node tools/release-validation/run.mjs --python "/path/to/python3.12" --go "/path/to/go" --cargo "$(rustup which cargo)"
```

1 つ目のコマンドは外部ネットワークを使用しません（1 つのテストが、ループバックの HTTP サーバーからインデックスを配信します）。2 つ目のコマンドは npm、PyPI、Go のプロキシ、crates.io からダウンロードを行い、Chrome を必要とします。`--lane` と `--catalog` で一部だけを選択でき、その場合の結果は PARTIAL になります。CI では、*Release validation* ワークフローを手動で開始します。要件、オプション、レポートの構成は、[ツールの README](../../../../tools/release-validation/README.md) に記載されています。

サードパーティーの依存関係は、コミットされたロックから取得するか（`locked`、デフォルト）、その時点で解決します（`fresh`）。Python のロックは、macOS arm64 と Linux x86_64 の CPython 3.12 用に用意されています。それ以外のインタープリターやプラットフォームでは、Python のレーンに `fresh` が必要です。

<a id="not-covered"></a>

## 対象外

- 上記の 6 つ以外のバージョン、およびこれらのレジストリに公開されていないもの。フレームワーク統合、Docker イメージ、プロジェクトテンプレート、サービス、コントラクトです。
- 実行されなかったオペレーティングシステム、アーキテクチャー、インタープリター、ブラウザー。具体的には、Windows、arm64 向けの Go バイナリ、Chrome 以外のブラウザーは対象外です。
- ホスト自体のツール。npm、pip、Go、cargo、rustc、C コンパイラー、Chrome は、ホストにあるものをそのまま使用して記録するだけで、固定はしません。
- カタログ自体が対象としていない性質。その制限は、[適合性キット](../../../../tools/conformance/README.md)と[監査ドシエ](../../../../docs/conformance/AUDIT_DOSSIER.md#known-limits-and-exclusions)に記載されています。
